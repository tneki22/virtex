# Virtex

Локальный тренажер для подготовки к экзамену по базам данных. Приложение открывает основной экзамен сразу с маршрута `/`, поддерживает режим изучения, режим изучения 2 с RAG по документам, пробный экзамен, заметки, голосовой ввод и AI-проверку ответов через OpenRouter или GroqCloud.

## Запуск

Требуется Node.js 22.12 или новее и npm 10 или новее.

```powershell
npm ci
npm run app
```

После запуска откройте `http://127.0.0.1:4173`.

Для разработки с автоматической перезагрузкой:

```powershell
npm run dev
```

## Материалы к экзамену

Файлы для раздела "Материалы к экзамену" лежат в папке `materials/` в корне проекта. Сервер читает эту папку динамически: если добавить, удалить или заменить файл, список на странице экзамена обновится без правок в React-коде.

Поддерживаются любые типы файлов. По нажатию на материал браузер открывает файл по адресу `/materials/<имя-файла>` или скачивает его, если формат не поддерживается для просмотра.

## Настройка AI

Скопируйте `.env.example` в `.env` и укажите ключ OpenRouter или GroqCloud. Провайдера, модель текста, модель распознавания речи, embedding-модель OpenRouter и режим streaming для tutor-чата можно выбрать в интерфейсе приложения.

Runtime-настройки сохраняются в локальной SQLite базе `runtime/virtex.sqlite`. API-ключи не возвращаются браузеру.

## Режим изучения 2: RAG по документам

Режим изучения 2 находится на маршруте `/exams/:examId/document-study`. Это чат по выбранному документу: пользователь выбирает источник, подготавливает индекс, создает чат и задает вопросы. В ответе показываются найденные источники: страница, `fragmentId` и оценка похожести.

Как это устроено:

- документы для поиска задаются в `content/exams/database-fundamentals/manifest.json` через `searchable: true`; сейчас индексируются `detailed-answers` и `textbook`, а список официальных вопросов не индексируется;
- при сборке контента `scripts/compiler.ts` извлекает текст из PDF через `pdfjs-dist`, привязывает его к номеру страницы и режет длинный текст страницы на фрагменты до 1200 символов;
- при подготовке индекса сервер отправляет тексты фрагментов в embedding-модель OpenRouter пачками по 32, нормализует векторы и сохраняет их локально в SQLite в таблицах `rag_documents` и `rag_embeddings`;
- при каждом сообщении в чате сервер отправляет в embedding-модель только текст вопроса пользователя, затем локально сравнивает этот вектор с сохраненными векторами выбранного документа;
- в prompt для AI попадает не весь PDF, а только найденные фрагменты: document tutor использует единый deep-профиль `topK: 10`, `neighborWindow: 2`, до 16000 символов retrieval-контекста и dedupe повторов;
- найденные фрагменты расширяются соседями по порядку документа и возвращаются блоками: сначала блок лучшего совпадения, внутри блока текст идет в естественном порядке источника;
- ответ строится через `buildDocumentTutorRequest` в `server/prompt.ts`: там есть метаданные экзамена и документа, retrieved-фрагменты, короткая история диалога и текущий вопрос.

Если в источнике ответа указана, например, страница 145, это не значит, что модели передали всю страницу как картинку или весь PDF. В текущем учебнике страница 145 разбита на два текстовых фрагмента: `textbook-p145-f1` на 1200 символов и `textbook-p145-f2` на 843 символа. Если поиск выбрал один из них, сервер может добавить соседние фрагменты по порядку документа. Именно эти текстовые куски с `documentId`, `page`, `fragmentId`, `score` и `text` попадают в `Document context`.

Примерный расход токенов считается внутренней оценкой проекта `ceil(JSON.stringify(messages).length / 3.5)`. После расширения RAG-бюджета насыщенный запрос в режиме изучения 2 ожидаемо тратит примерно 5500-8000 входных токенов и до 6000 выходных токенов; защитный ориентир для document tutor prompt — до 14000 входных токенов. Подготовка индекса считается отдельно: текущие compiled-документы дают примерно 21 тыс. embedding-входных токенов для `detailed-answers` и 110 тыс. для `textbook`; после этого на обычный запрос заново embedding-ится только вопрос пользователя. Увеличенный выходной лимит помогает, если модель раньше упиралась в `max_completion_tokens`; дополнительно prompt прямо просит не сжимать ответ искусственно, когда retrieved-контекст богатый.
