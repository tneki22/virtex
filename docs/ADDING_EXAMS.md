# Добавление экзамена

Новый экзамен подключается разработчиком как каталог `content/exams/<exam-id>`. Это намеренное ограничение первой версии: пользовательские документы не загружаются в runtime без предварительной проверки.

## Состав пакета

```text
content/exams/example/
  manifest.json
  questions.json
  style-guide.md
  documents/
    source.pdf
```

`manifest.json` задаёт ID и версию пакета, название, предмет, профили экзаменатора, документы, пороги готовности и правила экзамена. `questions.json` содержит независимые вопросы с официальной и отображаемой формулировками, эталоном, акцентами и ссылками на страницы или фрагменты источников.

Каждый профиль может задавать собственные быстрые промпты для учебного tutor-чата:

```json
{
  "id": "mentor",
  "name": "Наставник",
  "description": "Объясняет тему и помогает найти пробелы.",
  "tone": "supportive",
  "quickPrompts": [
    {
      "id": "everyday-example",
      "label": "Пример из жизни",
      "prompt": "Объясни тему пошагово на бытовой ситуации."
    }
  ]
}
```

Для рабочего пакета подготовьте минимум четыре сценария на профиль. `id` должны быть уникальны внутри профиля, `label` — коротким текстом кнопки, `prompt` — полным сообщением модели. Нажатие на кнопку только заполняет редактор и не отправляет запрос.

Режимы «Изучение» и «Экзамен», серии на `1`, `2`, `3` или `5` вопросов, история, заметки и голосовой ввод относятся к ядру приложения. Для их использования новый пакет не требует отдельной клиентской логики.

## Источник эталонов

Для каждого пакета заранее определите авторитетный документ с готовыми ответами. Текст `referenceAnswer` должен формироваться из него во время подготовки пакета. Дополнительный учебник используется только для ручного заполнения отсутствующих сведений с явной ссылкой на его страницу; runtime не объединяет документы и не создаёт эталон моделью.

В пакете `database-fundamentals` авторитетным источником является `detailed_answers.pdf`. Все 48 вопросов ссылаются на него, включая воспроизводимые правила для повторов и составного вопроса. Учебник остаётся дополнительным проверочным документом.

## Обязательные правила

- ID пакета, вопросов и документов уникальны и стабильны между версиями.
- Каждый вопрос содержит отдельный эталонный ответ.
- Каждая ссылка указывает на существующий документ и страницу.
- Цитаты должны подтверждаться извлечённым текстом документа.
- Вопросы с одинаковой темой остаются независимыми, если в официальном списке у них разные номера.
- Исправленная формулировка хранится в `displayText`, исходная — в `officialText`.
- `style-guide.md` должен быть коротким: он входит в каждый AI-запрос.
- Быстрые промпты профилей должны соответствовать их тону и не содержать эталонный ответ или скрытые инструкции по выставлению баллов.
- Порядок приоритета источников и ручные исключения должны быть воспроизводимы скриптом подготовки, а не храниться только в скомпилированном JSON.

## Компиляция

Для нового пакета запустите компилятор напрямую:

```powershell
npx tsx scripts/compile-exam.ts content/exams/example
```

Проверка без перезаписи результата:

```powershell
npx tsx scripts/compile-exam.ts content/exams/example --check
```

Компилятор извлекает текст, формирует fragment ID, проверяет документы, страницы, ссылки, ID и эталоны. При ошибке пакет не публикуется. После успешной компиляции перезапустите сервер: он автоматически обнаруживает все каталоги с `compiled/package.json`.

Для пакета баз данных используется полный цикл:

```powershell
npm run content:bootstrap
npm run content:build
npm run content:validate
```

## AI и калибровка

На один ход сервер передаёт модели только текущий вопрос, эталон, связанные фрагменты, краткие правила, профиль экзаменатора и ограниченный хвост текущего диалога. Полная история остаётся в SQLite. Контекст ограничен, а ссылки в ответе модели проверяются против реально переданных фрагментов.

Tutor-чат может использовать общие знания, жизненные примеры и аналогии, но не должен приписывать выдуманные сведения документам пакета. Проверка ответа использует отдельный структурированный JSON-контракт и после итоговой оценки закрывается для новых сообщений.

Перед использованием баллов нового экзамена как показателя готовности добавьте `calibration.json` с фиксированными полным, частичным, ошибочным, пустым, неподтверждённым и инъекционным ответами. Затем выполните:

```powershell
npx tsx scripts/calibrate-prompt.ts content/exams/example
```

Скорректируйте эталоны, акценты и промпт, если результаты выходят за ожидаемые диапазоны.

## Голосовой ввод

Транскрипция не зависит от структуры документов пакета. Сервер строит краткую подсказку Whisper только из предмета, формулировки и акцентов текущего вопроса. Эталонный ответ в подсказку распознавания не включается. Для работы требуется серверный `GROQ_API_KEY`; распознанный текст всегда остаётся редактируемым черновиком и не отправляется на проверку автоматически.
